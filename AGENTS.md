# Работа с IZO ASA Platform

Минимальный вход: этот файл → docs/STATUS.md → карточка нужного пакета в docs/NEXT.md → одна предметная страница по docs/INDEX.md → нужный source/test. Команды находятся в README. Не читать весь комплект, старый IZO_ASA и исторические планы без конкретной необходимости.

1. Одна задача — одна ограниченная ветка и PR. До правки проверить remote, HEAD, status и чужие изменения. Не использовать reset --hard, force-push и cleanup чужого WIP.
2. Описать пользовательский результат, scope, non-goals, проверки и ограничения в PR. Отдельный многостраничный Task Contract для кнопки не нужен. Расширение scope объясняется до посторонних правок.
3. Чистые contracts/generation не импортируют HTTP, БД, SDK и секреты. UI не вызывает провайдеров и не содержит ключи. Общий HTTP-клиент один. Текущие DTO не объявлять готовой очередью.
4. Один responsive web app. Telegram/MAX — адаптеры, не копии приложения. Непроверенные initData, query parameters и JS globals не дают identity.
5. API/local jobs получают разные pools. Будущий GPU-worker использует исходящее HTTPS, не доступ к PostgreSQL и не роль CI-runner.
6. Unit/UI tests не используют production, платных провайдеров или GPU; сетевые вызовы fake/blocked. Compose integration работает только с изолированными DB/S3. Секреты не печатать.
7. Реальные платежи, письма, bot actions, деплой, DNS и ключи требуют отдельного разрешения владельца. Документация и технический review этого не разрешают.
8. После малой правки — профильная проверка. Не чинить production ради кнопки. Общий CI — при готовом PR, не после каждой строки. Проверки не ослабляются ради зелёного результата.
9. Не менять LICENSE, CI, миграции и правила контроля вместе с посторонней задачей. CODEOWNERS/AGENTS не заменяют branch protection и ограничение token permissions.
10. Не повышать limits ради прохождения gate. Выделять связную ответственность, не произвольные фрагменты. Generated файлы обновлять инструментом. Ограничения текущих tests не выдавать за контроль всех будущих границ.
11. Не обещать exactly-once внешнего provider. Unknown outcome требует reconciliation, не слепой повторной платной генерации. Баллы, provider cost и tokens coding-агента — разные величины.
12. Разделять IMPLEMENTED / TESTED / REVIEWED / PUSHED / MERGED / DEPLOYED / OPERATIONALLY VERIFIED. CI success проверять по steps и SHA. Viewport/SDK-hint emulation не доказывает работу настоящего Mini App.
13. Текущий foundation UI не является утверждённым дизайном. UX-001 должен получить отдельную визуальную приёмку; не размножать нынешнее оформление на новые функции. Адаптация включает QHD/«2K», 4K UHD и HiDPI/масштабирование по docs/UX.md, не только Full HD.
14. PRODUCT/ADMIN/UX/ARCHITECTURE/AI_RUNTIME — целевые контракты, STATUS — факты, NEXT — единственный план. Не создавать второй master plan и дублировать один статус в разных местах.
15. Новый provider или источник credentials подключать по разделам 9–10 docs/AI_RUNTIME.md. Не добавлять отдельные баланс, user identity, media ownership, job lifecycle или provider-specific fetch в UI. Секрет не является моделью или универсальной настройкой URL; каждый adapter имеет свой проверенный API-контракт.
16. Перед реализацией назвать сохраняемые инварианты и профильные negative tests. Если задача требует изменения общего контракта, остановить постороннюю реализацию, описать влияние/миграцию и получить отдельное согласование scope. Не переписывать спецификацию задним числом, чтобы оправдать отклонение.
17. Экранная задача указывает U/D-ID из PRODUCT или A/AD-ID из ADMIN; настройка — S-ID и apply/default/permission, пакет — NEXT. Читать только нужные карточки. Роль, состояние аккаунта, тариф и остаток независимы; frontend не назначает права. Для новых полей указать тип, ограничения, REQ/default, влияние на текущие jobs и отрицательные tests; не создавать экран/настройку вне реестра без изменения его документа-владельца.

## Подключение любого coding-агента

В начальном поручении явно указать repository, согласованные base SHA/ветку, ID задачи из NEXT и этот AGENTS.md. Перед правкой агент сообщает прочитанные предметные страницы, область изменений и команды приёмки. Нельзя считать инструкции прочитанными только потому, что файл существует.

Если инструменту нужен файл собственного формата, он должен быть коротким указателем на этот AGENTS.md, а не копией правил; такие адаптеры подключаются только для действительно используемых инструментов. Этот пакет не устанавливает и не настраивает отдельный coding-продукт.

Передача работы следующему агенту: branch/SHA, что изменено, команды и результаты проверок, оставшиеся ошибки и единственный следующий ограниченный шаг. Не передавать production-ключи и полный исторический чат. Один пишущий владелец для пересекающегося scope; самопроверка не называется независимым review.

Практический порядок работы и готовое поручение UX-001 — docs/DEVELOPMENT.md. Product AI не получает доступ coding-агента к GitHub или shell.
