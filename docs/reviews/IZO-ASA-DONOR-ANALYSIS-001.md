Это исторический снимок на указанном base. Последующие изменения чата и канонической ветки в таблицу не включены; актуальное состояние определяется `docs/STATUS.md`, а активный пакет — `docs/PLAN.json` и `docs/CURRENT.md`. До: прежний проект назван факультативным референсом, точные требования к современному чату, месту `Admin` и рублёвой цене не собраны. После: сопоставлены сценарии, дефекты и границы переноса. В каноническую ветку из стабильных правок перенесён целевой контракт [ADMIN](../ADMIN.md); предложения для PRODUCT, UX и AI_RUNTIME из исходного checkout не входят в этот diff. Не входят: импорт кода/БД/пользователей, UI/API, ключи, платные вызовы, публикация цен, merge/deploy.

## Дефекты донора, которые нельзя переносить

- [Старый chat review](https://github.com/spikeal8-maker/IZO_ASA/blob/93a0a9d/docs/chat-system.md#L485): CSS specificity ломает mobile tool menu; picker перегружен; отсутствуют streaming/cancel; Markdown неполон; image-tool результат привязывается best-effort PATCH; visual capability не проверяется до платного вызова; image data не проверяется по magic bytes; лимиты ответа и истории расходятся; нет канонического eval-набора. Это наблюдения исходного проекта, а не подтверждение исправлений здесь.
- [Старые настройки](https://github.com/spikeal8-maker/IZO_ASA/blob/93a0a9d/backend/main.py#L14598) меняют JSON без ожидаемой ревизии/preview публикации; коммерческие коэффициенты в старом коде — исторические значения, не утверждённая политика новой платформы.
- [Старый audit админских мутаций](https://github.com/spikeal8-maker/IZO_ASA/blob/93a0a9d/docs/admin-mutation-audit.md#L17) нашёл среди 19 критических routes 6 verified, 7 partial и 6 gap; повтор мог дать новый финансовый/entitlement effect. Нужны отдельные idempotency, race, reason и audit tests.
- Крупные old UI/backend файлы и стили уже мешают локальным правкам. Переносить договорённости и тестовые сценарии в малые owner-модули согласно MAINTAINABILITY, без копирования компонентов целиком.

## Последовательность реализации и приёмка

Это ориентир для отдельных конечных packages, не замена `PLAN.json`/`CURRENT.md` и не разрешение начинать следующий package минуя `begin-next`.

1. **Сверить state и существующий UX WIP.** Текущий checkout `ux/chatgpt-experience-001` расходится с веткой `feat/chat-deepseek-001`, записанной в `PLAN/CURRENT`; `project_state.py verify` не проходит. Сохранить существующие 29 незакоммиченных файлов; определить, что из них уже закрывает критерии ниже, затем перейти по штатному state workflow.
2. **Чатовый UI.** Expanded/compact/mobile sidebar, память состояния, центрирование относительно контента, доступный composer и модельный picker. Acceptance: desktop/mobile клавиатура, поиск/история/reload/long Russian text, Markdown и изображения; визуальное сравнение с согласованным ориентиром ChatGPT без копирования чужих assets.
3. **Вход Admin.** Кнопка между 3D и балансом, staff visibility и отказ backend при прямом URL/API, responsive nav. Acceptance: отсутствие пункта у обычного пользователя, запрет после отзыва grants, правильный порядок на desktop/телефоне.
4. **Каталог и цены.** Admin draft/preview/publish для provider/model/default и RUB price по token direction/image mode; отдельные permissions `catalog.write`, `connections.write`, `pricing.write`, audit и version conflict. Acceptance: missing provider price ≠ free, stale price видна, неподдержанный mode не публикуется, пользователь видит утверждённую цену до submit.
5. **Платный chat/tool runtime.** Quote/max/reserve/settle на общем Credits, verified usage, idempotency и unknown outcome reconciliation; image tool создаёт общий Job/Media asset. High-risk пакет с negative/race/restart tests и независимым review по MAINTAINABILITY. Реальные ключи/расходы требуют отдельного разрешения.
6. **Дальнейший функционал.** Студии, галерея/feed, тарифы/платежи, доставка/боты — по отдельным capability/permission пакетам после определения продуктовых правил и существующего coverage.

Открытые решения владельца для реализации цены: платить ли пользователю через общий баланс за платформенные ключи и как вести BYOK; курс/источник и срок действия FX; правила округления, резерва и маржи; цена image по count/size/mode. Ни одно старое значение не считается принятым автоматически.

## Протокол работы субагентов

Ниже — подготовленная схема исполнения, а не одновременно запущенные code packages. `PLAN.json` разрешает один активный пакет и одну каноническую линию. Независимые агенты могут одновременно исследовать донор, писать acceptance cases и проверять diff; код одного пакета меняет только назначенный implementer в объявленном machine scope. Интегратор (/root) фиксирует до → после, base, владельцев файлов, non-goals, риск и ближайший test; сравнивает diff со scope, собирает результаты и проводит SELF_REVIEW. Агент-ревьюер не переписывает тот же код параллельно. Для high-risk его локальный взгляд дополняет, но не заменяет структурированное GitHub `APPROVED` от другого actor на exact SHA либо предусмотренный правилами explicit owner waiver.

Их не добавляют скрыто в ближайший scope. Каждому пакету до кода назначаются точные owner файлы, ближайший failing/acceptance case, лимит `tiny/normal/cross_domain` и headroom по MAINTAINABILITY; следующий package начинается только после required tests, SELF_REVIEW, full CI, freeze и штатного `begin-next`/`begin-decided-next`.

## Самопроверка

Исходная задача анализа покрыта источниками, текущим состоянием, рисками и критериями переноса. Изменены только документация и scope; production-код, правила CI, secrets и финансовые операции не тронуты. `python tools/check_docs.py`, `check_change.py --base 3202908d... --scope tools/scopes/izo-asa-donor-analysis-001.json`, `git diff --check` и `export_contracts.py --check` прошли. Полный локальный `pytest` в Windows завершился `725 passed, 37 failed, 176 errors`: первая ошибка воспроизводится при создании `asyncio` loopback `socketpair` для Starlette TestClient, который запрещает unit-fixture `tests/conftest.py`; это не вызвано изменением документации. Linux CI не запускался, техническая приёмка/full CI не заявляется. Вердикт SELF_REVIEW: `PASS` для анализа и docs-only diff; `IMPLEMENTED` для UI/API не заявляется.
