# Продукт IZO ASA · спецификация 0.2

DOC-003, 8 сентября 2026. Это целевое поведение новой платформы, **не перечень уже работающих страниц**. Реализация — [STATUS](STATUS.md), последовательность — [NEXT](NEXT.md), оформление и QHD/4K — [UX](UX.md). Правила агентов — [AGENTS](../AGENTS.md).

Владелец подтвердил перезапуск без старой БД/аккаунтов, новую регистрацию и компенсацию по запросу; общую платформу web/Telegram/MAX, все пять AI-направлений, галерею, ленту и админку. Конкретные маршруты, семантика ограничений и технические значения ниже — предлагаемый контракт v0.2 для принятия, а не уже утверждённые цены, дизайн или права доступа в коде.

## 1. Назначение

Одно рабочее пространство: пользователь описывает задачу/прикладывает исходники, выбирает разрешённую модель, понимает максимальный расход, получает результат, хранит его приватно и при желании публикует. Один аккаунт, баланс, система заданий и владение файлами используются во всех клиентах. Новое подключение AI не создаёт вторую галерею или бухгалтерию.

Старая IZO_ASA — только явно запрошенный референс поведения; код, пользователи и база не импортируются. Компенсация оформляется в новом аккаунте по заявке, без автоматического сопоставления старых имён/email. Полный функциональный паритет старому сайту не является условием выпуска.

## 2. Понятия доступа

Роль/permissions, состояние аккаунта, способ подтверждения identity, версия тарифных возможностей, доступный баланс и состояние провайдера независимы. «Дорогой тариф» не означает «администратор», «Telegram» не означает «проверенный email», «ноль баллов» не означает «запрещено смотреть свои файлы».

Гость не имеет аккаунтной сессии. Пользователь действует от своего Account. Сотрудник — пользователь с отдельными серверными permissions и scopes из [ADMIN](ADMIN.md). Worker — технический субъект, который получает только выданные задачи; он не входит в пользовательские страницы и не получает PostgreSQL/ledger privileges.

Публичный код и имя предназначены для UI; неизменяемый internal ID — для связей. JS globals, query parameters, client user_id, IP, тариф и тип устройства не назначают полномочия.

## 4. Аккаунт — P-01/P-12

Регистрация не выдаёт staff-role. Web email подтверждается одноразовым challenge; ответ восстановления не раскрывает, существует ли чужой адрес. Сессии хранятся и отзываются сервером; пароль и открытые tokens персоналу не показываются.

Telegram/MAX start data проверяются backend по официальному алгоритму конкретной платформы, сроку и replay policy. Подтверждённый platform subject может быть способом входа без принудительного email; для email-уведомлений/восстановления требуется отдельно подтвердить адрес. Связывание доказывает владение обеими сторонами, конфликт существующего аккаунта не решается слиянием по имени/аватару.

Последний работающий способ входа нельзя отвязать. Смена чувствительных данных требует свежего подтверждения. Отзыв сессии прекращает последующие запросы. Границы ограниченного/заблокированного аккаунта заданы в §12, не определяются случайно на каждом экране.

## 5. Общий путь генерации — P-02…P-05

Перед резервом сервер проверяет identity, ownership исходников, entitlement, состояние capability, лимиты и цену. Клиент подтверждает действующую оценку, связанную с параметрами. Смена модели/размера требует новой оценки. Повтор идентичного submit возвращает тот же job; другой payload с тем же ключом — conflict.

Очередь и результат переживают закрытие браузера/Mini App и restart. Фаза выполнения отделяется от реально известного процента; выдуманный прогресс запрещён. Отмена после принятия провайдером не гарантирует остановку или возврат его расходов. Unknown outcome сверяется до новой платной отправки. Ошибка сохранения уже созданного результата не повод повторять генерацию.

Text-to-image: prompt, capability, поддержанный формат/размер, count и цена. Редактор работает с копией результата, маской и принадлежащими пользователю references; исходник не перезаписывается. Неподдержанный mode недоступен и в API, не только в меню.

Видео показывает duration, aspect/size, audio support, input limits и отдельную готовность poster/full file. Аудио различает речь/музыку/транскрипцию; отказ микрофону не ломает upload, autoplay со звуком запрещён. Клонирование голоса не входит в ранний выпуск без отдельной политики согласия.

3D хранит manifest ресурсов; picture preview не выдаётся за готовую модель. Формат, ресурсы и memory budget проверяются; на слабом устройстве остаются poster/download. Готовность к печати или совместимость с CAD не обещаются автоматически. Разрешение монитора 4K не меняет цену/разрешение генерации.

Подробный runtime, credentials и contract tests принадлежат [AI_RUNTIME](AI_RUNTIME.md), не дублируются в интерфейсных инструкциях.

## 6. Чат — P-06

Threads/messages имеют одного владельца. Streaming request имеет отдельный lifecycle; tool создаёт обычное generation job. Обсуждение идеи не запускает платную работу. Backend проверяет предложенный LLM tool: schema, ownership, permission, стоимость, согласие и общий лимит вызовов/расхода. Publish/delete требуют отдельного подтверждения.

История ограничена контекстным бюджетом; файлы — asset references, не повторяющиеся base64. Markdown безопасен. Web search даёт реальные источники, не выдуманные ссылки. Остановка/разрыв stream помечает частичный ответ; повтор не скрывает новый расход. Чат не получает GitHub-token, Docker socket, SQL или shell.

## 7. Приватные работы — P-07

Галерея использует общие assets, не отдельную файловую базу на каждую modality. Есть type/filter/sort/pagination, empty/loading/error и просмотр metadata. Скачивание/повторное использование каждый раз проверяют владельца и состояние файла. Избранное не делает asset общим.

Удаление объясняет зависимости: публикации, исходники активных jobs и срок очистки. Опубликованный original не удаляется обходным путём. Переполнение квоты блокирует новые объёмы, но не прячет уже сохранённые разрешённые работы и не запускает молчаливую автозачистку. Коллекции и batch-операции — дальнейшее развитие, не раннее требование.

## 8. Публичная лента — P-08

Publication ссылается на asset, но имеет свой title/caption, выбранные публичные поля, derivatives и moderation state. Private prompt/references по умолчанию исключены. В первый публичный feed включаются жалобы и модерация; комментарии/подписки/совместный remix не добавляются автоматически.

Снятие закрывает публикацию/производные и инициирует cache invalidation; уже скачанные чужими людьми копии нельзя обещать удалить. Обычный moderator читает предмет жалобы, не весь приватный аккаунт. Reaction/report идемпотентны в пределах операции и защищены лимитами.

## 9. Баллы и уведомления — P-09/P-11

Доступный остаток, активный резерв и окончательное списание отображаются отдельно. Баллы продукта не равны токенам LLM. Журнал исправляется компенсирующей проводкой, а не перезаписью прошлого. Компенсация имеет номер заявки и уникальный business key; доставка уведомления не повторяет начисление.

Успех генерации не зависит от доставки в Telegram/MAX/email. Private text и долгоживущие secret URLs не отправляются без основания. Ключи/пароли нельзя запрашивать в обращении. Оплата считается подтверждённой только по проверенному событию/сверке провайдера, не по redirect браузера.

## 10. Как читать постраничный контракт

Ниже — реестр **заявленного объёма v0.2**, а не обещание всех мыслимых функций. U — экран/route, D — диалог или sheet; вкладки названы внутри строки. В рамках одного клиента используется один UI, не отдельные копии для desktop/phone/Telegram/MAX.

Маршруты предлагаются как каноническая карта для будущей реализации. Сейчас Foundation может использовать другие пути; DOC-003 router не меняет. При вводе нового маршрута нужны redirect/deep-link tests, сохранение безопасного returnTo и корректный Back. Не перенаправлять неизвестный URL молча на «Создать». Системный callback не обязан присутствовать в меню.

Обозначения доступа: G — гость; M — доверенная ограниченная сессия до необходимого подтверждения; V — active с подтверждённым способом входа; OWN — проверка владельца; PUB — только опубликованные/разрешённые данные. Любой доступ дополняется §12 и feature gate. S из ADMIN относится только к персоналу.

Горизонты: **A** — минимальная закрытая image-alpha; **L** — обязательно перед публичным запуском соответствующей включённой возможности; **E** — расширение, включать после своего этапа. Выбор первого публичного scope фиксируется LAUNCH-001, а не наличием пунктов меню.

Общие состояния для всех U: загрузка, пусто, недоступный сервис/сеть, повтор, session expired/denied, not found/deleted. Приватный чужой ID не раскрывает факт существования. Для мутаций: validation, submitting, duplicate/conflict и success receipt. Данные формы сохраняются безопасно, секреты — нет. Для всех U/D действуют focus/keyboard/touch/long-text и QHD/4K/HiDPI из UX; только screenshot недостаточен.

### Диалоги и панели — не отдельные копии страниц

Каждый D имеет loading/validation/busy/error/success, focus-return и безопасное закрытие; используется тем же компонентом как dialog/sheet по устройству. Результат мутации принадлежит серверу. Этап наследуется от родительской U и указанного домена.

## 12. Матрица доступа и приоритет отказов

### Состояния аккаунта — предлагаемый контракт

| Состояние | Чтение и восстановление | Новые расходы/записи | Текущие задачи |
|---|---|---|---|
| Без действующей сессии | Публичное + вход/восстановление | Нет account mutations | Продолжаются сервером, после входа OWN |
| Нуждается в подтверждении | Свой профиль/безопасность, подтверждение и помощь | Нет generation/publish/purchase; подтверждение/выход разрешены | Не должно быть штатных paid jobs до допуска |
| Active | OWN и PUB по permissions | Только при entitlement/лимитах/балансе | Обычный lifecycle |
| Generation suspended | Свои разрешённые работы/баллы/support, сессии | Нет новых generation/chat sends/publish/upload; исправление профиля, отзыв и обращения доступны | Queued отменяются с освобождением; уже принятые сверяются/завершаются по policy, не повторяются |
| Security locked | Нет обычного private API; только отдельная проверка восстановления/контакт | Никаких privileged/account операций до восстановления | Stop новых dispatch; принятые изолированы/reconcile, без автоматических повторов |
| Deletion pending | Ограниченная OWN session для статуса/отмены в пределах grace | Нет новых работ/покупок/публикаций | Drain/cancel по runtime; публикации скрываются; purge учитывает references/обязательное хранение |
| Deleted | Только публичное и новый signup как новый Account | Нет доступа к старым объектам | Согласованная очистка/хранение без доступной старой session |

Generation suspension и security lock — разные административные команды с причиной. Запрос удаления не подтверждает возможность мгновенно удалить финансовые записи/backup. Сроки хранения и обязательные исключения принимаются до публичного выпуска.

### Тариф, лимиты и деньги — не состояние аккаунта

| Ситуация active-пользователя | Свои работы/скачивание/история | Новая генерация | Публикация/общение |
|---|---|---|---|
| Ноль доступных баллов | Разрешены, пока файл хранится и не ограничен по безопасности | Только явно бесплатная capability с ненулевой квотой; paid denied | Просмотр/снятие/поддержка не требуют оплаты; публикация только по entitlement |
| План истёк | Не отбирать уже сохранённые разрешённые файлы и купленный остаток | Новые запросы по действующему базовому плану | Права персонала не меняются вместе с тарифом |
| Превышена storage quota | Читать/скачивать/удалять по обычным правилам | Блокировать новые объёмы без резервирования места; no silent eviction | Не делать original публичным ради экономии |
| Достигнут concurrency/rate limit | Разрешены | Понятный отказ/retryAfter; не создавать бесконечные queued reservations | Действует отдельный лимит конкретной операции |
| Capability не входит в план/выключена | Архив результатов читается независимо от нового каталога | Отказ до вызова/резерва | Не переключать на другую платную модель молча |
| GPU недоступен | Сайт/галерея/API-подключения не блокируются | Local отказ/очередь по явной policy; API отдельно | Feature-specific деградация |

Приоритет проверки защищённой операции: действующая session → security/deletion status → permission/ownership → feature gate → identity requirement → entitlement → provider availability → лимиты → средства. Публичная read-route проверяет publication policy без обязательной session. Только проверки, относящиеся к действию, применяются: для OWN download не нужны цена, доступность GPU и текущая подписка модели.

Denial возвращает безопасные reason codes: auth_required, verification_required, account_restricted, forbidden, not_found, feature_unavailable, plan_restricted, provider_unavailable, quota_exceeded, rate_limited, insufficient_credits. Для чужого private ID — not_found без metadata; для известного own action допустима объясняющая причина. Никакого расхода при отказе. Frontend badges не заменяют серверную проверку.

### Продуктовые профили возможностей

| Профиль | Назначение | Отличие |
|---|---|---|
| `basic` | Базовый доступ активного аккаунта | Allowlist capabilities/executors и конечные квоты; наличие плана не обещает бесплатных баллов |
| `extended` | Опциональное расширение на срок | Больший/иной набор разрешённых возможностей, срок действия; не staff-role |
| `custom` | Индивидуальное назначение по сроку/основанию | Явная версия назначения, оператор и audit; не магическое «всё без лимитов» |

Названия внутренние, предложенные; коммерческие названия/цены владелец пока не утвердил. Пробный бонус — отдельная проводка с policy, не скрытый admin-тариф. На alpha достаточно `basic` и ручных начислений; остальные профили можно не включать. Service worker не является пользовательским планом. Сотрудник, использующий обычную студию, проходит обычную проверку бюджета; бесплатный staff bypass запрещён.

Entitlements версионируются. Итоговый набор — пересечение одной effective revision плана, допустимых capabilities приложения, ограничений аккаунта/scope и доступного connection. Индивидуальное расширение оформляется явной custom revision с audit, не staff-role и не случайной суммой планов. Даже custom не расширяет технические ограничения модели или security policy. Несколько подписок автоматически не суммируются; правила дополнений требуют отдельного контракта перед их введением.

| Поле entitlement | Семантика |
|---|---|
| capability_ids / executor_types | Явные allowlists; пусто = запрет, не все модели |
| active_jobs / submissions_per_window | Первый считает queued/claimed/running/uploading/reconciling; второй новые принятые операции в скользящем окне, не polling/идемпотентный repeat |
| storage_bytes / upload_bytes / input_count | Учитывать committed assets и зарезервированные uploads/outputs; reclaim после фактической безопасной очистки |
| image_sizes / video_seconds / audio_seconds / mesh_limits | Только пересечение с capability/adapter и серверными hard bounds |
| chat_context_tokens / tool_calls / max_credits_per_action | Контекст и side effects ограничены раздельно; превышение требует новой разрешённой операции |
| can_publish / can_react | Отдельно от хранения и генерации; guest read не даёт mutate |
| effective_from / expires_at | UTC; expired revision больше не разрешает новый submit, не меняет прошлый job snapshot |

Нулевой числовой лимит означает запрет. Null допустим только как явно описанное наследование от конечного default; неразрешённая конфигурация не публикуется. «Unlimited» не скрывается в -1/0. Quota/time/retention и цены не становятся произвольными числами агента: правила полей — ADMIN, решения — §13.

## 13. Решения перед включением и критерии приёмки

| Решение | Технический безопасный старт | Когда требуется решение владельца |
|---|---|---|
| Коммерческие планы/цены/бонусы | basic + тестовые начисления, покупки off | Перед реальным платным scope, не до UX-прототипа |
| Provider/model/budget/передача исходников | Канонический fal.ai adapter реализован; live key/spend acceptance выключена до отдельного разрешения | Каждое новое live-подключение и изменение provider/model/budget |
| Численные квоты/хранение/grace | Явные тестовые finite values; никакой автозачистки нужных файлов | До LAUNCH-001; обязательные поля блокируют публикацию config, не разработку |
| Матрица suspension/deletion и support | Предложение §12 и безопасные ограниченные команды | До реальных пользователей и очистки |
| Состав меню/после-входа/визуал | U-ID стабильны; routes v0.2 — проект | UX-001; переименование не меняет ownership/runtime |
| Юридические тексты/лицензия | Не сочинять утверждённые условия; LICENSE не меняется | До публичного выпуска/реальных payments |

Минимальные будущие acceptance cases: AC-01 guest и чужие U-18/U-20/U-36 denied; AC-02 unverified не генерирует и может подтвердиться; AC-03 ноль баллов сохраняет чтение архива; AC-04 expired plan не стирает ledger/assets; AC-05 quota blocks new bytes, не чтение; AC-06 suspension/lock/deletion имеют разные права; AC-07 idempotency/cancel не удваивает расходы; AC-08 staff-role и план независимы; AC-09 identity link не объединяет чужие аккаунты; AC-10 callbacks/deep links не обходят доступ; AC-11 hidden publication не выдаёт private original; AC-12 один набор правил для web/Telegram/MAX.

Для каждой реализуемой U/D агент указывает ID, конкретный вход, данные/действия, разрешённый и запрещённый сценарии, сохранение после refresh и UI-states; привязывает tests к ID. Это требования к будущим tests, не утверждение об их наличии. На публичный launch выдаётся список включённых U и отключённых E, а не обещание всего реестра.

Отложено за рамки v0.2: комментарии/подписки, коллекции, batch, команды/совместные проекты, партнёрский API, voice cloning, referrers/promos и social syndication. Для них сначала добавляется ограниченная карточка, затем код; нынешний реестр не разрешает их реализовывать «заодно».
